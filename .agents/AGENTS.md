# AGENTS.md

Guidance for AI coding agents (Codex, OpenCode, Kiro, GitLab Duo, and any
AGENTS.md-aware runtime) working on this repository. The root `AGENTS.md`
symlink points here so spec-compliant tools auto-discover this file.

This is a Terraform module for AWS maintained by SUDO Consultants, generated
from the sudo-terraform-module-template. The README documents the module for
consumers; this file documents how to work on it.

## Dev environment tips

- Run `make setup` once to install terraform-docs and pre-commit hooks
  (commit-msg and pre-push included).
- `make help` lists all developer shortcuts.
- The module root requires Terraform >= 1.3.0 and AWS provider >= 6.0.0
  (see `versions.tf`); every example directory has its own `versions.tf`.
- Project-specific agent skills live in `.claude/skills/`; `.agents/skills`
  is a symlink to that same directory - edit skills in one place only.

## Code conventions

- Standard module files: `main.tf`, `variables.tf`, `outputs.tf`,
  `versions.tf`, plus `examples/minimal/` and `examples/complete/`.
- `snake_case` names; the primary resource is named `this`.
- Every variable needs `type` + `description` (defaults and validations where
  sensible); every output needs `description`. Lint fails without them.
- Always thread a `tags` variable onto every taggable resource.
- Security defaults are hardened (encryption on, no public access, least
  privilege IAM); checkov blocks CI on any finding in the module root.
- Comments use `#`. The README tables between `BEGIN_TF_DOCS`/`END_TF_DOCS`
  are generated by `make docs` - never hand-edit them.

## Testing instructions

- `make fmt` then `make lint` then `make checkov` must all pass before a
  change is complete. `make validate` runs `terraform validate`.
- `make pre-commit` runs the full hook suite against all files - this mirrors
  what CI (`.github/workflows/main.yml`) enforces.
- When the module API changes, update `examples/` so both examples still apply
  cleanly.

## PR instructions

- Never commit or push directly to `main`/`master`; local hooks reject both.
  Work on a feature branch.
- Commit messages follow Conventional Commits v1.0.0. Allowed types: `feat`,
  `fix`, `docs`, `chore`, `refactor`, `test`, `ci`, `perf`, `build`,
  `revert`.
- Run `make docs` before committing if variables or outputs changed.
- CI must be green (pre-commit job + checkov job) before merge.
